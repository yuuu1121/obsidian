# 세미나 노트 — Koopman 편대제어 + LiDAR 판 검출·헤딩·쓰러스터 파이프라인

발표 준비용 정리. 모든 수치·수식은 저장소 코드와 `research/` 문서에서 직접 확인한 값이다(파일:라인 병기). 발표 흐름 순서로 배열: **① 제어 이론(Koopman) → ② 지각(LiDAR) → ③ 실행(쓰러스터) → ④ 결과·발견**.

## 1부 — Koopman 기반 편대제어는 어떻게 작동하나

### 1.1 문제 설정: 편대제어를 "효용 극대화"로 바꾼다

전통적 편대제어(합의제어, MPC 등)와 달리, Tao & Zhao(2023, arXiv 2305.03777/03778)의 프레임워크는 로봇이 원하는 모든 거동(목표 접근, 순항, 충돌회피…)을 **하나의 스칼라 효용함수**로 합친다:

```
u_i(k) = Σ_j ω_i^(j) · φ_i^(j)(X(k))        (로봇 i의 효용, X = 전체 상태)
```

제어 문제는 "다음 스텝의 효용을 최대화하는 가속도 입력 U를 골라라"가 된다. 동역학은 이중적분기(위치·속도, 제어=가속도):

```
X(k+1) = A·X(k) + B·U(k),   A = [[I, dt·I],[0, I]],  B = [[dt²/2·I],[dt·I]]   (sim/dynamics.py:3)
```

N=3 로봇이면 X ∈ R¹²(위치 6 + 속도 6), U ∈ R⁶, dt = 0.05 s.

### 1.2 효용함수의 항들 — 각 거동이 항 하나씩

원논문 6항 + 본 연구 확장 3항. 구현은 `sim/utility.py:6-50`(`phi_robot`), 로봇 i에 대해 r* = pos_i − target_i, nr = |r*|, nv = |v_i|:

| 항 | 수식 (코드 그대로) | 의미 | 가중치(실기) |
|---|---|---|---|
| φ¹ | `(r*·v)/(nr·max(nv,0.05))` | 진행방향 정렬 코사인 | −1 |
| φ² | `1−exp(−((nv−v_des)/v_w)²)` | 순항속도 이탈 벌점 | −1 |
| φ³ | `exp(−(nr/4)²)·exp(−(nr/6)²)` | 목표 근접 보상 | +5 |
| φ⁴ | `exp(−(nr/0.05)²)·exp(−(nv/0.05)²)` | 목표점 정지 보상 | +2 |
| φ⁵ | `ln(1+6·exp(−40·d_wall))` | 벽 근접 벌점 | −2 |
| φ⁶ | `ln(1+10·exp(−20·d_ij))`, d_ij = min 로봇간 표면거리 | 로봇간 충돌회피 | −2 |
| **φ⁷** | `Σ_(i,j)∈E exp(−(‖p_i−p_j‖−d*)²/σ²)` | **편대유지 (본 연구 기여)** | +3 |
| φ⁸ | `ln(1+10·exp(−20·(‖p_i‖−0.65)))` | 리더(플랫폼) 반발 | −32 |
| φ⁹ | `−‖p_i − target_i‖²` | 위치 비례 복원 | +50 |

실기 가중치 벡터: `w_robot = [−1,−1,5,2,−2,−2,3,−32,50]` (`relative_state.py:99` — w₈·w₉는 격자탐색 실측 근거가 주석에 남아 있음).

**φ⁷ 설계의 요점** (`draft/phi7-design.md`):
- 원논문 φ⁶(멀수록 좋음)을 "목표거리 d* 근처에서 최대"인 Gaussian으로 일반화. Gaussian은 원논문 함수족(φ³·φ⁴) 안에 이미 있음.
- 엣지 집합 E는 **최소 강성(minimally rigid) 그래프**(|E| = 2N−3): 형상이 반사 하나 빼고 유일 결정 + 편대 항 결합이 N에 **선형**(전체쌍 C(N,2)면 조합 폭발).
- φ⁶(근거리 척력)과의 역할 분리: `d* − 2R ≥ 0.5 m`이면 목표거리에서 φ⁶ 간섭이 φ⁷ 복원력의 1% 이하 — 가중치 튜닝 없이 구조적으로 분리.
- σ는 "편대오차 포획 반경"이자 2차 근사의 유효 반경(σ = 0.5·min d* 권장).

### 1.3 Koopman 아이디어: 왜 효용함수를 상태변수로 올리나

효용은 X의 비선형 함수라 "u를 최대화하는 U"는 원래 비선형 최적화다. Koopman 접근의 핵심 발상:

**비선형 함수 값 자체를 상태벡터에 추가(lifting)하면, 확장된 공간에서 동역학이 (근사적으로) 선형/bilinear가 된다.**

```
z(k) = [ z⁽¹⁾ ; z⁽²⁾ ],   z⁽¹⁾ = X (원상태 — 선형·정확),
                          z⁽²⁾ = 로봇별 φ 값들 (비선형 — 근사 대상)
```

z⁽¹⁾의 전이는 A, B로 정확하다. 문제는 z⁽²⁾(k+1) = φ(AX+BU) — 이걸 어떻게 z(k), U(k)의 함수로 쓰나?

**bilinear 근사** = 동작점 x₀ = [z⁽¹⁾₀; z⁽²⁾₀; U₀=0] 둘레 **2차 Taylor 전개** 후 UᵀHU 항만 버림 → 결과가 **U에 대해 affine**:

```
z⁽²⁾(k+1) ≈ (z, z⊗z 항들) + (z에 의존하는 계수)·U
```

U-affine이라는 성질이 결정적이다 — 목적함수 max w·z⁽²⁾(k+1)이 U의 **선형 함수**가 되어 LP로 풀 수 있다. 회귀벡터는 `ζ = [z1d, z2d, U, 1, z1d⊗z1d, z1d⊗z2d, z2d⊗z2d, z1d⊗U, z2d⊗U]` (`sim/koopman.py:11-21`), 차원:

```
a(N,m) = (6N+m+1) + 24N² + 6Nm + m²
```

N=3, m=18(6항×3로봇)이면 a=901 — 원논문 ζ∈R⁹⁰¹과 일치(검산: `sim/tests/test_koopman.py:5-9`). φ⁷ 추가(m=21)면 1075, N=7이면 5727. RLS의 P 행렬이 a×a라 메모리 8a² 바이트(N=10이면 1.08 GB) — 확장성 분석(기여 C3)의 뼈대.

**파라미터 식별은 온라인 RLS** (`sim/rls.py:11-20`, EDMD 배치 식별은 저장소에 없음):

```
ε = Θᵀζ − y,   m² = ρ + ζᵀPζ,   Θ ← Θ − Pζεᵀ/m²,   P ← P − PζζᵀP/m²
```

ρ=1e-4, P₀=100I, P 리셋 주기 linear 130 / bilinear 75 스텝.

### 1.4 제어: LP → 그리고 실제로 쓰는 것

Θ̂를 알면 다음 스텝 가중효용이 U-affine: `w·z⁽²⁾(k+1) ≈ (상수) + c·U`. c 추출은 블록 인덱싱 없이 평가로 한다(`sim/control.py:5-12`): `c_l = w·(Θᵀζ(U=e_l) − Θᵀζ(U=0))`.

풀이(`sim/control.py:14-30` `solve_input`)는 두 갈래:

```python
if reg > 0:  u = clip(c / reg, u_min, u_max)          # 정규화 QP — 폐형식, solver 불요
else:        linprog(−c, bounds=박스)                  # 순수 LP — 항상 ±u_max 꼭짓점 (릴레이)
```

**세미나에서 정확히 말해야 할 사실 3가지:**

1. **순수 LP는 릴레이다.** 제약이 박스 바운드뿐이라 해는 항상 꼭짓점 = 매 틱 ±u_max 뱅뱅 제어. 참 상태(GT)에서는 유효했지만(게이트 S3, max_edge 0.233 m), **추정치 기반 출력피드백에서는 한계사이클로 발산**했다(편대오차 2.7~10.8 m — 지각을 아무리 개선해도 못 닫음). 그래서 QP 정규화(λ=1)로 전환: `u = clip(c/λ, ±0.3)` — 그래디언트 크기가 곧 추력 크기가 되는 비례 제어로 순화. λ∈{1.0,1.3,1.6,2.0} 스윕에서 1.0이 단조 최적(`relative_state.py:58-62`).
2. **데이터 기반 식별 팔은 두 번 기각됐다.** 수치 캠페인: 공개 설정만으로는 a=901 vs 표본 300, rank 270(영공간 ≥631)의 **미결정계**라 Θ의 그래디언트 부호일치율이 동전던지기(46.7~55.6%) — 재현 불가 확정. Stonefish 폐루프에서도 식별 팔은 54~147 m 발산. 다만 하위 속도루프로 동역학이 정형화된 계층 구조에서는 **온라인 식별 자체(게이트 S2)는 성립**한다(bilinear 1-step RMSE < linear).
3. **그래서 기본 제어 팔은 "해석적(analytic)"이다** (`sim/experiment.py:90-99`): 모델 Θ 없이, 참 효용함수에 유한차분을 걸어 참 그래디언트를 직접 계산 — `c_l = [w·z2(AX + B_l·h) − w·z2(AX)]/h`, h=1e-4. E1~E4 5/5, Stonefish 전 게이트가 이 팔로 통과했다. 식별 팔은 비교군으로 코드에 보존.

**지연 보상**: 실선박 동역학에서 U→실가속 작동지연 τ=0.16 s 실측(교차상관). 그래디언트를 현재 상태가 아니라 τ만큼 전파한 상태에서 계산: `c = analytic_c(A_d·X + B_d·u_prev, …)` (`koopman_node.py:235`). 대조실험에서 τ=0.10→오차 0.011 m, τ=0.15→0.273 m의 절벽 — 릴레이+지연 한계사이클이 원인임을 확정했던 수정이다.

### 1.5 시뮬 → 실기 이식: 계층형 아키텍처

수치 시뮬(이중적분기)에서 검증된 파이프라인을 Stonefish 실선박 동역학에 이식할 때, **end-to-end 스러스터 식별이 아니라 계층 분리**를 택했다:

```
[상위 20 Hz]  koopman_formation: 상대상태 X → 효용 그래디언트 → QP → 가속지령 accel_cmd
[하위 20 Hz]  velocity_loop ×3: accel_cmd 적분 → 속도 PI + 베어링 요 제어 → 4ch 쓰러스터 setpoint
[리더]        leader_pilot: Koopman 밖 외생 입력, P 웨이포인트 추종
```

상태는 전부 **리더(플랫폼) 기준 상대좌표**(pos−p_L, vel−v_L)로 조립(`relative_state.py`) — 목표·동작점이 상대좌표로 상수화되어 sim/ 수학 모듈(utility·koopman·rls·control)을 **수정 없이 재사용**한다. 편대 기하: 플랫폼 중심 정삼각형, 변 1.5 m, `OFFSETS = [(0.866,0), (−0.433,0.750), (−0.433,−0.750)]`.

## 2부 — LiDAR로 판(plate)을 검출하고 헤딩을 뽑아 쓰러스터를 돌리기까지

### 2.0 전체 흐름 한 줄

```
OS0-128 점군 → 앙각 컷 → BEV 밀도맵 → 연결성분 → 라인 세그먼트 → 판 형상 게이트
→ 3D 재적합 → 시간 필터·트래커 → boxes → (브리지) 중심·헤딩 복원 → KF/EMA/전역배정
→ state_est → [상위] Koopman QP → accel_cmd → [하위] 속도 PI + 베어링 요 → 4ch setpoint
→ 8ch RPM → CAN(실기) / Stonefish(시뮬)
```

핵심 설계 원칙 둘: **검출 경로는 실기·시뮬이 같은 노드**(파라미터만 다름, 커밋 6fee7a7), 그리고 **검출은 반사강도가 아니라 순수 기하**로 한다(강도 게이트 전부 OFF — 실물 판 강도가 7~45라 이진 강도 가정이 실기에서 깨짐, `perception.launch.py:51-58`).

### 2.1 왜 판인가 — 마커의 진화

gtbot은 준원판형 + 스러스터 90° 배치라 형상만으로 헤딩이 약관측(C4 대칭 모호). 1차 해법은 높이가 다른 기둥 2개(방위각 차 = 헤딩, 모호성 0)였으나, 실물 랩 파이프라인이 **14×10 cm 반사판 1장**이어서 실물 정합을 위해 판으로 교체했다. 대가: 판은 π-대칭이라 **180° 모호성이 구조적으로 남는다**(§2.4에서 접기로 처리).

시뮬 쪽 함정 하나(9차 캠페인의 발견): 판이 시각 메시에만 있고 **물리(충돌) 메시에 없으면 LiDAR 레이캐스트가 판을 한 번도 못 맞힌다** — 실제로 검출되던 건 돔 상판이었고 헤딩 오차 6°가 요지부동이었다. 판을 충돌 월드에 박스로 추가하고(`gtbot_world.scn:238-259`, 0.138×0.008×0.098 m), 판 장축을 몸체 y축과 정렬(rpy −1.5708)하자 헤딩 오차가 **6.0° → 0.5°**로 떨어졌다. 판 장착각은 지각이 "헤딩 = 적합선 + 90°"로 계산하므로 **알려진 상수**여야 한다(22° 틀어지면 68° 편향 → 45° 이상치 게이트가 est 전량 기각 → 시스템 붕괴 실측).

### 2.2 판 검출 — `ouster_cluster_node` (C++, 실기·시뮬 공용)

RANSAC이 아니다. **BEV(조감) 밀도맵 + 연결성분 + 형상 게이트** 파이프라인(`src/ouster_cluster/`):

**(1) 앙각 컷** (`elevation_filter.hpp:26`): `z ≥ r·tan(min°) ∧ z ≤ r·tan(max°)` — atan2 없이 레이 앙각 밴드만 통과.

**(2) 프리프로세스** (`plane_detect.hpp:46`): 거리 컷(실기 3 m/시뮬 5 m) + z 크롭. 강도 컷 0(꺼짐).

**(3) BEV 밀도맵** (`bev_density.hpp:145`): 2 cm 셀에 점을 떨어뜨리되,

```
density(cell) = Σ_p (x²+y²)   ← 점수 × 거리²
```

r² 가중이 LiDAR의 1/r² 밀도 감쇠를 상쇄해 **거리 불변 밀도**가 된다. 셀 생존 조건 = 밀도 임계(실기 7.0/시뮬 3.0) + **수직성 게이트**(z-빈 2개 이상 점유 — 바닥면은 1빈이라 탈락) + 외톨이 셀 제거. 반 셀 시프트 이중 격자(dual_grid)로 격자 경계 우연성 완화.

**(4) 라인 세그먼트** (`bev_lines.hpp:88`): 생존 셀들을 **8-이웃 연결성분**으로 묶는다. 연결 시 z 정합 검사 3단(점 수준 과반 접촉 → 셀 중앙값 높이 차 → z-range 겹침 폴백) + 대각 이웃은 양쪽 직교 셀 존재 시에만(모서리 누수 차단). 헤더 주석이 명시하듯 "떨어져 있지만 우연히 공선인 셀들은 절대 한 세그먼트가 못 된다 — 전역 RANSAC과의 차이". 세그먼트 게이트: 셀 5개 이상, 폭 ≤0.09 m, 길이 0.05~0.25 m.

**(5) 판 형상 판정 2단**:
- 1차(`isPlateSegment`, `bev_lines.hpp:476`): 길이 ≈ 0.14 m(±0.05), 높이 ≈ 0.10 m(±0.04~0.05)
- 2차(`recoverPlateCluster`+`fitRectangularPlate`, `plane_detect.hpp:301,109`): 세그먼트 씨앗 주변 3D 크롭 → 유클리드 클러스터링(씨앗 최근접 선택) → 마할라노비스 트림(χ² 7.815) → 3D 공분산으로 **두께**(최소고유값 축 스프레드) ≤ 0.03 m(실기)/0.12 m(시뮬), 폭·높이 재확인. "얇고 납작하고 크기가 맞는 것"만 판.

**(6) 시간 필터 2겹**: 연속 confirm_frames 출현해야 발행 + 확정 후 max_missed 드롭아웃 견딤(실기 10/2, 시뮬 2/10 — 부유 표적은 파도 히브로 명멸), 그 위에 등속 예측 + EMA 보정 트래커(`bev_tracker.hpp`, yaw는 π·π/2 대칭 접기 후 EMA α=0.2).

**출력**: `/ouster_cluster/boxes` — OBB를 LINE_LIST 24점 와이어박스로 발행.

### 2.3 위치·헤딩 복원 — `platform_perception` (Python 브리지)

**(1) 박스 해독** (`perception_core.py:78` `decode_wirebox`): 중심 = 24점 평균, 판 장축 방향 = 첫 에지 방향.

**(2) 좌표 변환** (`perception_core.py:7` `lidar_to_world`): LiDAR FLU → body(y 미러) → 월드(`R(+yaw_p)`, 플랫폼 IMU yaw). 독스트링에 4개 부호 조합 전수 검증 기록 — 이 조합만 GT에 0.003~0.014 m로 붙는다. **이 변환 때문에 플랫폼 IMU가 모든 로봇 추정에 공통 인자로 실린다.**

**(3) 헤딩 수식** (`platform_perception.py:128`):

```
line_yaw_world = yaw_p − line_yaw_flu          (FLU y미러의 θ→−θ)
heading_raw    = line_yaw_world + π/2           (판 장축 ⊥ 로봇 헤딩)
heading        = fold_heading(heading_raw, expected)
                 expected = atan2(−y, −x)       ("팔로워는 플랫폼을 본다" 사전정보
                                                  — 기대에서 90° 초과면 π 더해 접기)
origin         = 판중심 − R(heading)·marker_offset
                 marker_offset = (0.0014, −0.1386) m
```

marker_offset 보정을 빼먹으면 판까지의 거리가 그대로 위치오차가 된다 — 실제로 세 대 모두 위치 RMSE가 정확히 0.1386 m(=|offset|)에 고정됐던 실측이 도입 근거. π-접기는 판의 180° 모호성에 대한 **원리적 한계** 처리다: 기대 헤딩에서 90° 넘게 벗어난 자세는 복원 불가(`perception_core.py:96-97`) — 운용 요건으로 "초기 배치에서 판이 플랫폼을 향해야 한다"가 나온다.

**(4) 필터 층 — EKF가 아니라 선형 KF + 각도 EMA + 전역 배정 3종**:

| 층 | 구현 | 요점 |
|---|---|---|
| 위치·속도 | 등속 선형 KF (`perception_core.py:105`) | 관측이 위치뿐·선형이라 EKF 불요. q=0.5 m/s², r=0.025 m(S4 실측 RMSE로 설정). 유한차분 속도는 잡음을 1/dt 증폭(σ≈0.35 m/s, SNR≈1)해 릴레이 부호를 잡음이 정했음 — KF가 그 대체 |
| 헤딩 | 각도 EMA α=0.5 + 품질 게이트 (`platform_perception.py:301-313`) | 라인피팅 기울기 표준오차 ≤0.12 rad일 때만 갱신 — 판이 비스듬해져 기울기 분산이 폭발하는 프레임 선별 차단 |
| 검출↔로봇 연관 | 전역 최적 배정, 사전식 목적 (`perception_core.py:147`) | 탐욕 최근접은 트랙 기아(한 번 굶으면 영구 미아)를 만들었다 — "배정 개수 최대 우선, 그 안에서 거리합 최소"로 전수 탐색((n+1)³) |
| 공백 처리 | KF 코스팅 <0.8 s | 등속 예측을 valid로 발행해 짧은 검출 명멸을 메움 |

**출력**: `/gtbotN/state_est = [rel_x, rel_y, rel_vx, rel_vy, yaw_world, valid]` — 플랫폼 기준 상대위치·속도 + 월드 절대 헤딩.

### 2.4 IMU 융합 — 두 지점, 그리고 "왜 그렇게 느리게"

**지점 1(플랫폼)**: 플랫폼 IMU yaw가 모든 검출의 월드 변환에 실린다(§2.3-2).

**지점 2(각 로봇) — 진짜 융합** (`velocity_loop.py:197-205, 277-279`): 로봇은 자기 IMU(hwt9053 AHRS)를 고주파 헤딩으로 쓰고, LiDAR 판 헤딩을 **저주파 절대 기준**으로 오프셋만 천천히 보정한다:

```
err     = wrap(yaw_lidar − yaw_imu)
yaw_off ← yaw_off + k_yaw_off · wrap(err − yaw_off)     (k_yaw_off = 0.005 @10 Hz ≈ τ 20 s)
yaw     = wrap(yaw_imu + yaw_off)                        (제어에 쓰는 헤딩)
```

갱신 게이트 3중: est 연속 유효 ≥3 s + 준정지(|gyro_z|<0.05 rad/s) + |err−yaw_off|<45°(π-접힘 이상치 차단). **τ≈20 s로 느린 이유가 이 시스템 이해의 핵심**: 오염된 측정 → 제어 → 자세 회전 → 검출 상실 → 더 오염, 이라는 폐루프 결합을 시정수 분리로 끊는다. k를 0.02로 올린 런에서 요 스윙 91~123°·S6 붕괴가 실측됐다. (일반 상보필터 `cf_update`도 코드에 있지만 제어에는 안 쓴다 — π-접힘 측정이 CF를 오염시켜 자기유지 발산을 만든 실측 이후 이상치 게이트 기준으로만 남음.)

근거 실측: 실기 IMU 정지 55분(`imu_run1`)에서 yaw 드리프트 raw 1024°/h, ddpm 모드 32°/h → ddpm 채택, 시뮬은 그 값(램프 1.565e-4 rad/s + 랜덤워크)을 shim으로 주입해 정합.

**지표 구분(발표 때 반드시)**: 헤딩 성능 수치는 두 기준이 있다 — **추정오차** |est−GT| = 순수 지각 성능(판 반영 후 중앙값 0.5°, IMU 0.1°), **조준오차** |est−베어링| = 지각+제어 추종 혼합(1.0~1.2°, 게이트 S5 기준). 판 반영 전에는 추정오차가 6°로 커서 둘이 겹쳐 보였지만 지금은 갈라진다 — 표마다 어느 기준인지 명시.

### 2.5 제어 → 쓰러스터 출력

**상위(koopman_formation, 20 Hz)**: state_est 3대분으로 X∈R¹² 조립 → 지연 보상(τ=0.16 s 전파) → 해석적 그래디언트 c → `U = clip(c/1.0, ±0.3)` → `/gtbotN/accel_cmd`.

안전 게이트 사슬(`koopman_node.py:141-249`): 부트스트랩(전 로봇 est 유효 3 s까지 완전 침묵) → 로봇별 est 홀드 1 s(만료 로봇만 침묵) → 한 대라도 5 s stale이면 **전원 침묵**. 그리고 **두절 시 zeros를 발행하면 안 된다** — velocity_loop의 두절 판정이 accel_cmd *신선도* 기준이라, zeros도 매 틱 오면 "a_cmd=0 유지"로 해석돼 로봇이 마지막 속도로 영구 항해한다(5분 방치 30~60 m 이탈 실측). 침묵해야 0.5 s 두절 감속 경로가 발동한다.

**하위(velocity_loop ×3, 20 Hz)** — 여기가 PI다:

```
병진:  v_ref += a_cmd·dt;  v_ref를 실측속도로 되끌기(τ=0.5 s);  |v_ref|≤0.2 클램프
       e = v_ref − v_world;  데드밴드 0.03;  적분 ei(안티윈드업)
       e_body = R_body(e + (ki/kv)·ei)
요:    yaw_ref = atan2(−rel_y, −rel_x)      ← 플랫폼을 바라보는 베어링 (판을 LiDAR에 계속 보이게!)
       내부 기준을 0.3 rad/s로 슬루, syaw = clip(kpsi·wrap(yaw − yaw_ref_track), ±0.06)
```

세부 근거 셋: ① v_ref 되끌기(vref_tau) — 순수 적분 v_ref는 플랜트가 못 따라가면 위상이 100° 벌어지고 감속 지령이 v_ref를 **회전**시켜 로봇이 공전(주기 5~7 s)했다. ② syaw 캡 ±0.06 — 정·역추력 비대칭 탓에 공통모드가 크면 기생 병진력→이탈→더 큰 syaw 폭주. ③ 부호: `[a,a,a,a]`는 yaw를 감소시킨다(개루프 실측) — 부호를 뒤집으면 정귀환 자전. est 두절 시 폴백 사슬(src=0 est → 1 스트릭 미충족 → 2 odom 베어링 → 3 마지막 베어링 유지 → 4 배치 상수), a_cmd 두절 시 위치 P-홀드.

**믹서(4ch)** (`mixer.py:32`): `sx,sy = clip(kv·e_body, ±0.7)`, `sw = clip(syaw, ±0.3)`,

```
[E, W, N, S] = clip([−sy+sw, +sy+sw, −sx+sw, +sx+sw], ±1.0)
```

포화 3단(병진 0.7 → 요 0.3 → 합성 1.0) — 병진 오차가 커도 요 권한이 0으로 잘리지 않게 **권한 예약**. 이게 없을 때 yaw가 자유 드리프트해 "축간 혼입"으로 보였던 게 게이트 S1의 첫 번째 수정이었다.

**RPM 변환·최종단**: `thruster_bridge`가 4ch setpoint를 역산해 수평 4추력기 믹스(`strafe_mix=[−1,1,1,−1]`, `yaw_mix=[−1,1,−1,1]` — 키보드 조종 실증 매핑) 후 `rpm = clip(±max_rpm·out)`, max_rpm=2000 → `/gtbotN/thruster_rpm`(8ch, 수직 4ch=0). 실기는 `thruster_can_node`가 CAN(0x300+i, int32 LE, 500 kbps)으로 송신, 시뮬은 `rpm_to_sim`이 브리지의 정확한 역산으로 Stonefish에 주입 — **제어~RPM 전 구간이 실기·시뮬 바이트 동일**.

### 2.6 지각-제어 결합: 이 시스템의 진짜 어려움

이 파이프라인의 교훈적 발견들 — 지각과 제어가 폐루프로 얽혀서 생긴 문제가 대부분이다:

1. **닭-달걀 부트스트랩**: 판은 입사각에 민감 → 지향 유지(bearing 제어)가 필요 → bearing은 state_est가 필요 → est는 검출이 필요. 해소: 요 제어로 판을 플랫폼 쪽으로 계속 지향 + 부트스트랩 유예 + 폴백 베어링.
2. **편대 붕괴의 인과 사슬**(2026-08-17 규명): LiDAR 발행률 점진 열화(10→2.5 Hz) → 검출 간격이 0.5 s 신선도 게이트 초과 → 틱의 83~87%가 제어 도달 전 추력 0 반환 → 편대 벌어짐 → 거리·입사각 악화로 검출 더 감소(양성 되먹임). 범인은 제어법칙이 아니라 **신선도 게이트와 발행률의 상호작용**.
3. **파괴점은 절벽**: 검출 누락 저하 스윕에서 임계 ≈65% — 그 아래는 전 수준 통과, 그 근처는 동전 던지기. 열화가 선형으로 성능을 깎는 게 아니라 임계에서 붕괴한다.
4. **φ⁶은 리더를 모른다**: 팔로워간 거리만 보므로 수렴 중 플랫폼 관통 → LiDAR 근접 사각지대 진입 → 침묵 정지. φ⁸(리더 반발) 도입으로 해소.
5. **φ¹은 스케일 프리**: 정규화 코사인이라 릴레이(방향만)에선 무해했지만 QP(크기=추력)에선 3.5 m 밀려나도 복귀 지령 ≈0. φ⁹(위치 비례 복원) 도입 근거.

### 2.7 실기 전환 시 남은 지점 (질문 대비)

- `velocity_loop` 속도 피드백의 실기 속도원(GPS/DVL 등) 결정 — 시뮬 한정 단순화가 남은 마지막 구간.
- `hwt9053_driver`가 stale — 실기 자세 토픽 `imu/ddpm`이 저장소 드라이버에 없어 launch의 리맵이 현재 무효(문서화된 알려진 갭).
- 캘리브레이션 노브 명시: `strafe_mix`/`yaw_mix`/`invert`/`max_rpm`(물에서 재보정), `kpsi`(실기 요 플랜트 상이), 판 장착각(알려진 상수 필수), 검출기 시뮬 보정 파라미터 7종(랩 튜닝값과 다름).
- 실기 boxes 경로의 2D PCA는 광선-회귀가 아니라서 주축 회전 편향(광선 방향 계통 오차, 시뮬 실측 15°)에 노출 — 실기에서 헤딩 계통편향이 보이면 1순위 용의자.
