# API와 클래스·객체

> [!abstract] 한 줄 요약
> **API**는 "이 부품을 어떻게 조작하면 되는지 적힌 사용설명서"이고, **클래스**는 그 부품을 찍어내는 "틀(설계도)", **객체(인스턴스)**는 그 틀로 실제로 찍어낸 "물건 하나하나"다. Gym은 모든 강화학습 환경에 **똑같은 사용설명서(API)** 를 붙여서, 환경이 무엇이든 같은 방식으로 다룰 수 있게 만든다.

## 1. API란 무엇인가?

**API**는 Application Programming Interface의 줄임말이다. 풀어 쓰면 *"프로그램이 다른 프로그램과 대화하는 규칙"* 이다.

> [!example] 비유 — 자판기
> 자판기 안의 복잡한 기계 장치(모터, 센서, 결제 시스템)를 몰라도, 우리는 **"버튼을 누른다 → 음료가 나온다"** 라는 규칙만 알면 자판기를 쓸 수 있다. 이 "버튼 누르기 규칙"이 바로 자판기의 API다.
>
> 마찬가지로, TV 리모컨의 버튼 배치도 일종의 API다. 삼성 TV든 LG TV든 "전원 버튼을 누르면 켜진다"는 **규칙(인터페이스)** 만 같다면, 내부 회로가 완전히 달라도 사용자는 신경 쓸 필요가 없다.

RL에서 API가 중요한 이유: 만약 환경마다 사용법이 다 다르면(어떤 환경은 `env.go()`, 어떤 환경은 `env.move()`…), 새 환경을 쓸 때마다 에이전트 코드를 처음부터 다시 짜야 한다. Gym(그리고 그 후속인 Gymnasium)은 **모든 환경에 `reset()`, `step()` 이라는 똑같은 두 함수**를 붙여서, 이 문제를 해결한다.

## 2. 클래스(class)와 객체(object) — 붕어빵 틀과 붕어빵

> [!important] 핵심 비유 — 붕어빵
> - **클래스(class)** = 붕어빵 **틀(모양을 찍어내는 틀)**. "이 모양대로 만들어라"는 설계도일 뿐, 그 자체는 먹을 수 없다.
> - **객체(object) / 인스턴스(instance)** = 틀로 실제로 구워낸 **붕어빵 하나하나**. 팥이 든 것, 슈크림이 든 것처럼 내용물(속성값)은 다를 수 있지만, 모양(구조)은 같다.

파이썬 코드로 보면:

```python
class Environment:          # ← 이것이 클래스(틀). "환경이라면 이런 모습이어야 한다"는 설계도
    def __init__(self):
        self.steps_left = 10  # ← 이 객체만의 속성(내용물)

env = Environment()         # ← 틀로 실제 물건을 하나 "찍어낸다" = 객체 생성(인스턴스화)
```

- `class Environment:` 는 "환경이라는 것은 이런 기능을 갖는다"는 **설계도**만 정의한다. 이 줄만으로는 아무 일도 일어나지 않는다.
- `env = Environment()` 를 실행해야 비로소 **실제로 메모리에 존재하는 물건(객체)** 하나가 만들어진다. 이 물건을 `env`라는 이름으로 붙잡아 둔 것이다.
- 붕어빵 틀 하나로 붕어빵을 100개 구울 수 있듯, `Environment()` 를 여러 번 호출하면 서로 독립된 환경 객체를 여러 개 만들 수 있다. `env1 = Environment()`, `env2 = Environment()` 는 서로 다른 붕어빵(`steps_left` 값이 각자 따로 줄어듦)이다.

### 메서드(method) — 붕어빵이 할 수 있는 동작

클래스 안에 정의된 함수를 **메서드**라 부른다. `env.get_observation()` 처럼 "점(.) + 함수 이름"으로 부른다. 이는 "이 객체에게 이 동작을 시켜라"라는 뜻이다.

```python
def get_observation(self) -> List[float]:
    return [0.0, 0.0, 0.0]
```

여기서 `self`는 "**나 자신**"을 가리키는 특별한 첫 번째 매개변수다. `env.get_observation()` 이라고 부르면, 파이썬은 자동으로 `self` 자리에 `env`(그 객체 자신)를 넣어준다. 즉 "너의 내부 상태를 기준으로 관측값을 돌려줘"라는 뜻.

### 상속(inheritance) — 자식이 부모의 기능을 물려받는다

Gym의 `Wrapper` 클래스는 `Env` 클래스를 **상속**한다 (`class Wrapper(Env)` 형태). 비유하면, "붕어빵 틀"을 기본으로 하되 그 위에 무늬를 하나 더 새긴 "장식 붕어빵 틀"을 만드는 것과 같다. 기본 기능(반죽 붓기, 굽기)은 그대로 물려받고, 거기에 새 기능(무늬 새기기)만 추가한다. 자세한 예시는 [[Wrapper 래퍼 패턴]] 참고.

## 3. 왜 이 개념이 Gym을 이해하는 데 필요한가?

Gym의 모든 환경(`CartPole`, `Breakout`, …)은 **`Env`라는 하나의 클래스를 상속**해서 만들어진다. 그래서:
- 어떤 환경이든 객체를 만들면(`env = gym.make("CartPole-v1")`), **똑같이** `env.reset()`, `env.step(action)` 을 호출할 수 있다.
- 이것이 가능한 이유는 모든 환경이 `Env`라는 같은 "틀(부모 클래스)"에서 나왔고, 같은 API(사용설명서)를 따르기 때문이다.

## 세 줄 정리
- **API** = 내부 구조를 몰라도 쓸 수 있게 해주는 "사용설명서(규칙)"
- **클래스** = 붕어빵 틀(설계도), **객체(인스턴스)** = 그 틀로 찍어낸 실제 붕어빵 하나
- Gym의 모든 환경은 같은 부모 클래스(`Env`)를 상속해 같은 API를 갖는다 → 환경이 바뀌어도 에이전트 코드는 그대로 재사용 가능
