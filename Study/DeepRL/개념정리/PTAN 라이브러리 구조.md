# PTAN 라이브러리 구조

> [!abstract] 한 줄 요약
> **PTAN(PyTorch AgentNet)** 은 RL 코드에서 매번 반복되는 "지루한 배관 작업"(에이전트가 행동을 고르고, 환경과 주고받고, 경험을 저장하는 일)을 대신해 주는 **부품 상자**다. Agent, ActionSelector, ExperienceSource, ReplayBuffer, TargetNet 다섯 부품을 조립해서 DQN 같은 방법을 훨씬 짧은 코드로 짤 수 있다.

## 1. 왜 이런 라이브러리가 필요한가?

[[Chapter 06]]에서 짠 기본 DQN은 학습 코드 약 200줄 + 환경 래퍼 50줄로, 그렇게 길지는 않았다. 하지만 문제는 **반복**이다. RL 방법은 CartPole이든 Atari든 "에이전트가 관측을 보고 → 행동을 고르고 → 환경에 실행하고 → 보상을 받고 → 경험을 저장한다"는 **똑같은 틀**을 공유한다. 이 틀을 새 프로젝트마다 새로 짜면:
- 코드를 복사·붙여넣기 하다가 **버그가 스며들기 쉽다**.
- 잘 만들어져서 여러 프로젝트에서 검증된 코드가 보통 **품질(성능·테스트·문서)** 이 더 좋다.

> [!example] 비유 — 레고 부품 상자
> 매번 블록을 처음부터 깎아 만들지 않고, 이미 만들어진 표준 블록(바퀴, 창문, 문)을 조립해 자동차를 만드는 것과 같다. PTAN은 RL 세계의 표준 블록 세트다.

## 2. PTAN이 제공하는 5가지 핵심 부품

| 부품 | 역할 |
|---|---|
| **Agent** | 관측(observation)들을 받아 실행할 행동(action)들로 바꾸는 클래스. 필요하면 내부 상태(state)도 유지 |
| **ActionSelector** | 신경망 출력(Q값·확률)에서 실제 행동 값을 골라내는 작은 로직. Agent와 짝을 이뤄 동작 |
| **ExperienceSource** | Agent + 환경을 가지고 궤적(trajectory)의 각 조각을 순서대로 만들어 주는 클래스 |
| **ExperienceSourceBuffer(리플레이 버퍼)** | 경험 조각을 저장했다가 무작위로 꺼내 쓰는 저장소. 단순 버퍼와 우선순위 버퍼 두 버전 제공 |
| **TargetNet** | 학습 중인 신경망과 "얼려둔" 목표 신경망을 동기화해 주는 유틸리티 |

이 외에도 PyTorch Ignite와 연동하는 헬퍼, Atari용 Gym 래퍼(6장에서 본 것과 비슷)를 제공한다.

> [!important] 균형 잡기 — 너무 딱딱하지도, 너무 자유롭지도 않게
> RL 라이브러리는 보통 두 극단 중 하나로 치우친다.
> - **극단 1 (너무 경직)**: 라이브러리를 불러와 몇 줄만 쓰면 끝 (예: Stable-Baselines3). 라이브러리가 하라는 대로만 하면 편하지만, 조금만 특이한 걸 하려 하면 라이브러리와 싸우게 된다.
> - **극단 2 (너무 자유)**: 리플레이 버퍼·궤적 처리를 전부 처음부터 직접 짠다. 자유롭지만 지루하고 실수하기 쉽다.
>
> PTAN은 **고품질 부품을 제공하되, 필요하면 언제든 서브클래스로 바꿔 쓸 수 있게** 두 극단의 중간을 노린다.

## 3. 이 책에서의 위치

이 챕터에서 배우는 PTAN 부품들은 이후 챕터(특히 8장 DQN 확장판들, Part 3의 정책 기반 방법들)에서 **똑같은 도구로 반복 사용**된다. 그래서 "어떤 방법을 쓰는지"에 집중하고, "경험을 어떻게 저장하고 꺼내는지" 같은 배관 작업은 PTAN에 맡기게 된다.

## 세 줄 정리
- PTAN은 RL 코드에서 반복되는 배관 작업(행동 선택·경험 수집·저장·타깃망 동기화)을 부품화한 라이브러리다.
- 핵심 부품은 Agent, ActionSelector, ExperienceSource, 리플레이 버퍼, TargetNet 다섯 가지다.
- "라이브러리가 다 해준다" 와 "전부 내가 짠다"의 중간 지점을 노려, 편의성과 유연성을 동시에 잡으려 한다.
