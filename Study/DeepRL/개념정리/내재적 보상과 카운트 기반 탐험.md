# 내재적 보상과 카운트 기반 탐험 (Intrinsic Reward & Count-Based Exploration)

> [!abstract] 한 줄 요약
> 환경이 원래 주는 보상을 **외재적 보상(extrinsic reward)**이라 하고, 에이전트가 "이 상태를 얼마나 못 봤는지"를 스스로 계산해 추가로 주는 보너스 점수를 **내재적 보상(intrinsic reward)**이라 한다. 카운트 기반 탐험은 "적게 방문한 상태일수록 내재적 보상을 크게" 주어서, 에이전트가 새로운 곳을 스스로 찾아가도록 유도하는 방법이다.

## 1. 왜 필요한가 — 순수한 우연에 기대지 않기

[[엡실론-그리디 탐험]]은 그냥 확률 ε만큼 아무 행동이나 무작위로 시킨다. 문제는 이 방식이 **목적 없는 무작위**라는 점이다. 미로가 아주 크고 복잡하면, 무작위로 헤매다가 우연히 새로운 방을 찾아낼 확률이 너무 낮다.

> [!tip] 비유 — 방 탐험 게임
> 여러분이 방탈출 게임 100개짜리 건물에 들어갔다고 하자. 눈을 감고 아무 문이나 여는 것(무작위 탐험)보다, **"내가 아직 안 가본 문에 표시를 해두고, 표시 없는 문을 우선적으로 열어보는 것"**이 훨씬 효율적이다. 카운트 기반 탐험이 바로 이 "안 가본 곳 우선" 전략을 숫자로 구현한 것이다.

## 2. 핵심 아이디어 — 방문 횟수를 세서 보상으로 바꾼다

상태 $s$를 몇 번 방문했는지 세어 $N(s)$라 하면, 내재적 보상은 다음과 같이 정의할 수 있다.

$$r_i = c \cdot \frac{1}{\sqrt{\tilde{N}(s)}}$$

말로 풀면: *"이 상태를 많이 봤을수록($\tilde{N}(s)$가 클수록) 보너스는 작아지고, 처음 보는 상태($\tilde{N}(s)$가 작을수록)일수록 보너스가 커진다."* $c$는 이 보너스의 비중을 조절하는 하이퍼파라미터다.

- **외재적 보상(extrinsic reward)**: 환경이 원래 주는 보상. 게임 점수, 도착 보상 등.
- **내재적 보상(intrinsic reward)**: 에이전트가 자기 경험을 돌아보고 스스로 계산해 얹는 보너스. "새로움(novelty)"에 대한 보상이다.

최종 보상은 둘의 합이다: `reward = extrinsic + reward_scale * intrinsic`.

> [!important] 호기심 기반 탐험(curiosity-driven exploration)
> 극단적으로, 환경의 외재적 보상을 아예 무시하고 **내재적 보상만으로** 학습하는 방식도 있다. 이를 호기심 기반 탐험이라 부른다. 놀랍게도 "새로운 것을 보면 기뻐한다"는 원칙만으로도 꽤 괜찮은 정책이 학습되는 경우가 많다. 마치 아기가 딱히 보상이 없어도 신기한 물건을 만져보고 탐색하는 것과 비슷하다.

## 3. 상태가 너무 많을 때 — 해시와 의사카운트(pseudo-count)

상태가 몇 개 안 되는 표(tabular) 환경이라면 $N(s)$를 그냥 딕셔너리에 세면 된다(파이썬의 [[defaultdict와 Counter|Counter]] 같은 자료구조). 하지만 상태가 연속값이거나(예: 위치·속도 같은 실수) 이미지처럼 경우의 수가 무한에 가까우면, 정확히 같은 상태가 두 번 나오는 일이 거의 없다.

해결책 두 가지:
1. **해시(hash) 함수로 뭉뚱그리기**: 실수 관측값을 소수점 몇 자리에서 반올림해 "비슷한 상태는 같은 것으로 취급"한다. 예를 들어 위치 0.12345와 0.12341을 둘 다 0.123으로 반올림하면 같은 상태로 센다.
2. **의사카운트(pseudo-count)**: 상태를 직접 셀 수 없을 때, 신경망으로 **"이 상태가 얼마나 그럴듯한(익숙한) 상태인가"**를 나타내는 밀도 함수 $\rho(x)$를 학습해서, $\tilde{N}(x) = \rho(x) \cdot n(x)$ (밀도 × 총 방문 수)로 방문 횟수를 근사한다. 정확한 구현은 복잡해서, 이 책에서는 간단한 해시 방식만 다룬다.

## 4. 코드로 보는 감 — PseudoCountRewardWrapper

```python
class PseudoCountRewardWrapper(gym.Wrapper):
    def __init__(self, env, hash_function=lambda o: o, reward_scale=1.0):
        super().__init__(env)
        self.hash_function = hash_function      # 관측값을 "셀 수 있는 형태"로 바꾸는 함수
        self.reward_scale = reward_scale        # 내재적 보상의 비중
        self.counts = collections.Counter()      # 상태별 방문 횟수를 세는 표

    def _count_observation(self, obs) -> float:
        h = self.hash_function(obs)             # 관측값을 해시(반올림 등)로 변환
        self.counts[h] += 1                     # 그 상태를 한 번 더 봤다고 기록
        return np.sqrt(1 / self.counts[h])      # 방문 횟수가 많을수록 작아지는 보너스

    def step(self, action):
        obs, reward, done, is_tr, info = self.env.step(action)
        extra_reward = self._count_observation(obs)
        # 원래 보상(extrinsic) + 스케일 곱한 보너스(intrinsic)를 합쳐서 돌려준다
        return obs, reward + self.reward_scale * extra_reward, done, is_tr, info
```

한 줄씩 보면: `_count_observation`이 "지금 상태를 몇 번째 보는지" 세고 $1/\sqrt{N}$ 공식으로 보너스를 계산하며, `step`은 환경이 원래 주는 보상에 이 보너스를 더해서 에이전트에게 돌려준다. 이렇게 하면 에이전트 입장에서는 "새로운 곳에 가면 공짜 점수를 더 받는다"는 유인이 생긴다.

> [!warning] 주의 — 오프폴리시 방법과의 궁합
> DQN처럼 [[오프폴리시와 온폴리시|오프폴리시]] 방법은 리플레이 버퍼에 예전 보상값을 저장해 두고 나중에 다시 학습하는데, 내재적 보상은 학습이 진행되며 계속 변한다(같은 상태라도 나중엔 방문 횟수가 늘어 보너스가 작아짐). 그래서 보상을 훈련 중에 바꾸는 것이 이상적이진 않지만, 실제로는 어느 정도 잘 작동한다.

## 세 줄 정리
- 환경이 주는 보상은 **외재적**, 에이전트가 스스로 계산해 더하는 "새로움 점수"는 **내재적** 보상이다.
- 카운트 기반 탐험은 방문 횟수 $N(s)$가 적을수록 $1/\sqrt{N(s)}$ 공식으로 큰 보너스를 줘서, 안 가본 상태로 에이전트를 유도한다.
- 상태가 연속적이거나 너무 많으면 해시로 뭉뚱그리거나, 신경망으로 방문 확률을 추정하는 의사카운트를 쓴다.
