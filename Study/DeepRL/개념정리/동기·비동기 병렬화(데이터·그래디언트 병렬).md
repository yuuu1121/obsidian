# 동기·비동기 병렬화 (데이터 병렬 vs 그래디언트 병렬)

> [!abstract] 한 줄 요약
> 여러 환경을 동시에 돌려 [[A2C와 A3C|A3C]]를 구현하는 방법은 크게 두 가지다 — **데이터 병렬**은 자식 프로세스가 "데이터(transition)"만 모아 보내고, **그래디언트 병렬**은 자식 프로세스가 아예 "그래디언트"까지 계산해서 보낸다.

## 순차 방식의 한계

[[상관관계와 표본 효율성]]에서 배웠듯 A2C는 여러 환경의 데이터를 한 배치에 섞는다. 가장 간단한 구현은, [[ExperienceSource와 리플레이버퍼]]처럼 환경 여러 개를 배열로 주고 **번갈아 가며(round-robin) 하나씩 순서대로** transition을 받아오는 것이다. 이건 여러 환경과 "통신"은 하지만 진짜 **병렬(parallel)** 은 아니다 — 한 CPU 코어가 환경들을 순서대로 처리하므로, 컴퓨터의 여러 코어를 놀리는 셈이다.

![[fig_12_11.png]]
*그림 12.11 — 여러 환경을 순차적으로 오가며 학습하는 에이전트(진짜 병렬은 아님)*

## 데이터 병렬 (Data Parallelism)

**여러 개의 프로세스**를 두고, 각 프로세스가 하나 이상의 환경과 통신하며 transition $(s, r, a, s')$을 모은다. 이 표본들을 전부 **중앙의 프로세스 0번**으로 모아서, 거기서 손실을 계산하고 SGD 업데이트를 수행한다. 업데이트된 신경망 가중치는 다시 모든 자식 프로세스로 전파(broadcast)되어, 다음 데이터 수집에 최신 정책이 쓰이게 한다.

![[fig_12_12.png]]
*그림 12.12 — 데이터 병렬: 자식 프로세스들이 각자 환경에서 얻은 표본(samples)을 중앙(Process 0)으로 보내면, 그곳에서 학습(loss + SGD)을 수행하고 갱신된 신경망 가중치(net weights)를 다시 자식들에게 돌려준다*

> [!tip] 실전 구현 — 코드 한 줄로 병렬화하기
> 책에서는 Gymnasium의 `gym.vector.SyncVectorEnv`(환경 여러 개를 순차적으로 처리)를 `gym.vector.AsyncVectorEnv`(내부적으로 `multiprocessing`을 써서 진짜 병렬 처리)로 **바꿔 끼우기만** 하면 데이터 병렬 버전의 A3C가 된다. PTAN 라이브러리의 `VectorExperienceSourceFirstLast` 클래스가 이런 "벡터화된" 환경을 지원한다.

## 그래디언트 병렬 (Gradient Parallelism)

한 단계 더 나아간 방식이다. 자식 프로세스들이 데이터만 모아 보내는 게 아니라, **자기가 모은 데이터로 손실 계산과 역전파까지 직접 수행**해서 **그래디언트 자체**를 계산한다. 그 그래디언트들을 중앙 프로세스로 보내면, 중앙은 그것들을 그냥 **더해서(합산)** SGD 업데이트만 수행한다. 물론 업데이트된 가중치는 다시 모든 자식에게 돌려줘서 온폴리시 상태를 유지시킨다.

![[fig_12_13.png]]
*그림 12.13 — 그래디언트 병렬: 자식 프로세스들이 각자 손실과 그래디언트(grads)까지 계산해서 중앙으로 보내면, 중앙(Process 0)은 그래디언트를 합산(Σ grads)해 SGD 업데이트만 수행한다*

## 두 방식의 차이가 중요한 이유 — 연산 비용

두 그림이 비슷해 보여도 **계산 비용의 위치**가 다르다. A2C 최적화에서 가장 무거운 연산은 **손실 계산(순전파)과 그에 대한 그래디언트 계산(역전파)**이고, SGD 업데이트 자체(가중치에 스케일된 그래디언트를 더하는 것)는 매우 가볍다.

- **데이터 병렬**: 무거운 손실·그래디언트 계산을 전부 **중앙 프로세스 하나**가 떠맡는다. GPU가 여러 대라도 중앙이 병목(bottleneck)이 되기 쉽다.
- **그래디언트 병렬**: 무거운 계산을 **자식 프로세스들에 분산**시키고, 중앙은 단순히 숫자를 더하기만 한다. 그래서 여러 대의 GPU·여러 대의 컴퓨터로 확장하기에 훨씬 유리하다.

## 어떤 방식을 골라야 하나

> [!note] 선택 기준
> - GPU를 **한 대만** 쓴다면 두 방식의 성능 차이는 크지 않다. 이 경우 저수준 그래디언트를 직접 다룰 필요가 없는 **데이터 병렬이 구현이 더 간단**하다.
> - 여러 대의 머신에 걸쳐 **수십 대의 GPU**처럼 분산 자원이 풍부하다면 **그래디언트 병렬**이 확장성 면에서 더 낫다.

## 세 줄 정리
- 데이터 병렬은 자식이 "원본 데이터"만 모아 보내고, 무거운 손실·그래디언트 계산은 중앙 하나가 담당한다.
- 그래디언트 병렬은 자식이 손실·그래디언트 계산까지 끝내고, 중앙은 그래디언트를 합산만 한다.
- 자원이 GPU 한 대뿐이면 데이터 병렬이 간단하고, 여러 GPU·여러 머신이면 그래디언트 병렬이 더 잘 확장된다.
