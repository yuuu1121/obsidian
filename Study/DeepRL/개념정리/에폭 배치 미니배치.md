# 에폭 · 배치 · 미니배치 (Epoch, Batch)

> [!abstract] 한 줄 요약
> 데이터를 신경망에 넣을 때, 한꺼번에 다 넣지 않고 **적당한 크기로 잘라서(배치)** 여러 번 나눠 넣는다. 이 잘린 묶음이 **배치(미니배치)**, 전체 데이터를 한 바퀴 다 도는 것이 **에폭**이다.

> [!note] 왜 한 번에 다 안 넣나?
> 학습 데이터는 보통 컴퓨터의 메모리(CPU·GPU)에 한 번에 다 올릴 수 없을 만큼 크다. 설령 올라간다 해도, 데이터 전체를 보고 딱 한 번 크게 방향을 트는 것보다, **조금씩 자주 방향을 트는 것**이 경사하강 최적화에서 더 안정적이고 효율적이다.

## 1. 배치(Batch)와 미니배치(Mini-batch)

**배치**는 한 번의 학습 스텝에서 신경망에 동시에 넣는 데이터 샘플들의 묶음이다. 전체 데이터를 통째로 쓰면 "배치 학습(batch learning)", 아주 잘게 쪼개 쓰면(예: 32개, 64개씩) "미니배치 학습(mini-batch learning)"이라 부르는데, 실무에서는 거의 항상 미니배치를 쓰기 때문에 그냥 "배치"라고만 해도 보통 미니배치를 뜻한다.

> [!tip] 비유 — 책 한 권을 통째로 vs 챕터별로 공부하기
> 두꺼운 책 한 권을 한 번에 다 외우려 하면 버겁고 비효율적이다. 대신 챕터(배치)별로 나눠서 공부하고, 각 챕터가 끝날 때마다 "내가 이해한 만큼" 조금씩 지식을 업데이트하는 게 낫다. 신경망도 마찬가지로, 배치 하나를 볼 때마다 가중치를 조금씩 갱신한다.

## 2. 에폭(Epoch)

**에폭**은 전체 학습 데이터를 **한 번 처음부터 끝까지 다 사용**하는 것을 말한다. 예를 들어 데이터가 1,000개이고 배치 크기가 32개면, 약 32번의 배치 처리로 1 에폭이 끝난다. 보통 신경망은 데이터를 여러 에폭에 걸쳐 반복해서 본다.

```
전체 데이터 (1000개)
 ├─ 배치 1 (32개) → 가중치 갱신
 ├─ 배치 2 (32개) → 가중치 갱신
 ├─ ...
 └─ 배치 32 (남은 개수) → 가중치 갱신
   ─────────── 여기까지가 "1 에폭" ───────────
(다시 처음부터 반복 = 2 에폭째...)
```

## 3. PyTorch 학습 루프에서의 위치

```python
for batch_x, batch_y in iterate_batches(data, batch_size=32):
    batch_x_t = torch.tensor(batch_x)   # 배치 하나를 텐서로
    batch_y_t = torch.tensor(batch_y)
    out_t = net(batch_x_t)               # 신경망에 배치 통과
    loss_t = loss_function(out_t, batch_y_t)
    loss_t.backward()
    optimizer.step()
    optimizer.zero_grad()
```

이 `for` 루프 한 바퀴 전체(모든 배치를 다 도는 것)가 **1 에폭**에 해당한다. 이 루프 자체를 여러 번(여러 에폭) 반복하는 것이 일반적인 학습 방식이다.

## 세 줄 정리
- 배치(미니배치) = 한 번에 신경망에 넣는 데이터 묶음
- 에폭 = 전체 데이터를 한 번 다 처리하는 단위
- 학습은 보통 "여러 배치로 나눈 데이터를, 여러 에폭에 걸쳐" 반복해서 본다
