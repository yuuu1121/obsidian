# 타깃 네트워크(Target Network)와 부트스트래핑(Bootstrapping)

> [!abstract] 한 줄 요약
> 벨만 방정식은 "다음 상태의 Q값"을 이용해 "지금 상태의 Q값"을 계산하는데, 같은 신경망을 두 역할에 다 쓰면 스스로 꼬리를 쫓듯 학습이 불안정해진다. **타깃 네트워크**는 "다음 상태 값 계산 전용"으로 따로 복사본을 두고, 일정 주기마다만 갱신해서 이 문제를 잠재운다.

## 1. 부트스트래핑이란?

**부트스트래핑(bootstrapping)** 은 어떤 값을 추정할 때, **그 값 자체의 다른 버전(다음 스텝 값)을 이용해** 계산하는 방식을 말한다. 벨만 방정식의 Q-러닝 갱신식을 보자.

$$Q(s,a) \leftarrow r + \gamma \max_{a'} Q(s', a')$$

지금 상태 $s$의 Q값을 구하는 데, 다음 상태 $s'$의 Q값을 쓴다. 그런데 $Q(s', a')$도 결국 **같은 함수** $Q$로 계산된다. "내가 나 자신을 이용해 나를 개선한다"는 재귀적 구조, 이것이 부트스트래핑이다.

## 2. 왜 문제가 되나 — 제 꼬리를 쫓는 강아지

> [!tip] 비유 — 거울을 보고 거울을 고치기
> 삐뚤어진 거울을 "그 거울에 비친 모습"만 보고 고친다고 상상해 보자. 거울을 살짝 만지면, 비친 모습도 같이 바뀐다. 그럼 "아직도 삐뚤다"며 또 만지고, 그러면 비친 모습이 또 바뀌고… 기준점 자체가 계속 흔들리니 언제 다 고쳐졌는지 알 수 없다.

신경망 하나로 $Q(s,a)$와 $Q(s',a')$를 둘 다 계산하면 정확히 이 상황이 벌어진다. $s$와 $s'$는 **한 스텝 차이**라서 신경망 입장에서 거의 똑같아 보인다. $Q(s,a)$를 목표값에 가깝게 만들려고 신경망 파라미터를 업데이트하면, 그 부작용으로 $Q(s', a')$의 값도 같이 슬쩍 바뀌어 버린다. 그러면 방금 계산했던 목표값이 이미 낡은 값이 되어, 다음 순간 또 다른 목표를 쫓게 된다. 목표가 계속 움직이니 학습이 요동치고 발산하기 쉽다.

## 3. 해결책 — 목표를 잠깐 얼려두기

**타깃 네트워크**는 메인 네트워크(학습 중인 $Q$)와 **똑같은 구조를 가진 복사본** $\hat{Q}$를 하나 더 만들어, 다음 상태의 값을 계산할 때는 이 복사본만 쓰는 방법이다.

$$y = r + \gamma \max_{a'} \hat{Q}(s', a')$$

핵심은 $\hat{Q}$(타깃 네트워크)의 파라미터는 **매 스텝 업데이트하지 않고**, `SYNC_TARGET_FRAMES`(예: 1,000프레임)마다 한 번씩만 메인 네트워크의 최신 가중치를 그대로 복사해 온다는 점이다.

```python
if frame_idx % SYNC_TARGET_FRAMES == 0:
    tgt_net.load_state_dict(net.state_dict())
```

이렇게 하면 목표값 $y$가 최소 1,000프레임 동안은 **고정된 기준점**이 된다. 거울을 계속 흔들며 고치는 대신, "1,000번 만질 때마다 딱 한 번씩만 거울 위치를 최신 상태로 맞춘다"고 생각하면 된다. 그 사이에는 안정된 목표를 향해 착실히 학습이 진행된다.

## 4. 손실 계산에서의 위치

이 챕터의 `calc_loss` 함수를 보면 두 네트워크의 역할이 분명히 나뉜다.

```python
state_action_values = net(states_t).gather(1, actions_t.unsqueeze(-1)).squeeze(-1)
with torch.no_grad():
    next_state_values = tgt_net(new_states_t).max(1)[0]
    next_state_values[dones_t] = 0.0
    next_state_values = next_state_values.detach()

expected_state_action_values = next_state_values * GAMMA + rewards_t
return nn.MSELoss()(state_action_values, expected_state_action_values)
```

- `net`(메인 네트워크): 지금 상태의 Q값을 계산 — **경사(gradient)가 흐른다.**
- `tgt_net`(타깃 네트워크): 다음 상태의 Q값을 계산 — `torch.no_grad()`와 `detach()`로 **경사가 흐르지 못하게 막는다.**

즉 "목표를 계산하는 쪽"은 학습에 영향받지 않도록 완전히 분리해 둔 것이다.

## 세 줄 정리
- 벨만 방정식은 다음 상태의 Q값으로 지금 상태의 Q값을 갱신하는 **부트스트래핑** 구조다.
- 같은 신경망으로 둘 다 계산하면 목표값이 계속 흔들려 학습이 불안정해진다.
- 타깃 네트워크(주기적으로만 동기화되는 복사본)로 목표값을 잠깐 고정해 안정성을 확보한다.
