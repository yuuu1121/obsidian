# 임베디드 모터 제어 학습 로드맵

> [!info] 이 노트의 목적
> 제어 이론(MPC, 칼만 필터, Koopman)은 강하지만 임베디드 실무 경험이 0인 상태에서, **로봇/드론 액추에이터 제어 직무의 포트폴리오**가 나오도록 짠 학습 설계다. 장비는 당분간 NXP 키트 하나만 쓰고, 산출물은 GitHub 저장소와 이 볼트의 노트로 남긴다. 세팅 과정은 [[MCSPTE1AK144 S32K144 모터 제어 키트 세팅 매뉴얼]]에 있고, 이 노트는 그 다음부터의 계획이다.

> [!abstract] 설계 한 줄 요약
> **두 트랙을 여섯 단계로 짝지어 진행한다.** 트랙 A에서 MCU 주변장치 하나를 베어메탈로 익히면, 트랙 B에서 그 주변장치를 쓰는 FOC 모듈을 내 코드로 교체하고 NXP 원본과 측정으로 비교한다. 매 단계가 "돌아가는 모터 + 비교 그래프 + 노트 + Git 태그"를 남기므로, 어느 단계에서 멈춰도 포트폴리오가 된다.

---

## 1. 왜 이 구조인가

세 가지 접근을 비교했다.

| 접근 | 장점 | 단점 | 채택 |
|:---|:---|:---|:---|
| 바닥부터 (주변장치 → FOC 재구현) | 레지스터 수준 기초가 탄탄 | 모터가 다시 돌기까지 수개월, 동기 유지 어려움 | 트랙 A로 흡수 |
| 위에서 아래로 (데모를 한 층씩 교체) | 매 단계 결과물, 원본 대비 검증 가능, 이론 강점 활용 | 주변장치 지식이 산발적 | 트랙 B, 몸통 |
| 프로젝트 우선 (캡스톤 역산) | 임팩트 최대 | 미지수가 너무 많아 초반 좌절 확률 높음 | 5단계 캡스톤으로만 |

두 트랙을 같은 단계 안에서 **A → B 순서**로 묶으면 바닥부터 접근의 체계성과 위에서 아래로 접근의 결과물이 동시에 확보된다.

---

## 2. 진행 규칙 (모든 단계 공통)

1. **A 먼저, B 나중.** 한 단계 안에서 트랙 A(주변장치)를 끝내기 전에는 트랙 B(FOC 모듈)를 건드리지 않는다.
2. **원본과 스위치로 전환 가능하게.** 교체한 모듈은 `#define USE_MY_SVM 1` 같은 컴파일 스위치로 NXP 원본과 즉시 바꿔 낄 수 있어야 한다. 비교 실험이 곧 검증이고, 망가지면 원본으로 돌아간다.
3. **측정 없이는 완료가 아니다.** 각 단계의 "완료 기준"에 적힌 수치를 FreeMASTER 스코프/레코더로 실측해 그래프로 남긴다.
4. **노트 한 장, 태그 하나.** 단계마다 Obsidian 노트 하나(`0N. …`)와 GitHub 태그 하나(`phase-N`). 노트는 아래 네 꼭지로 고정한다.
   - 무엇을 만들었나 (구조 그림 하나)
   - 원본과 무엇이 다른가 (설계 결정과 이유)
   - 측정으로 무엇을 확인했나 (그래프 + 수치)
   - 막혔던 것과 푼 방법 (면접에서 가장 많이 묻는 부분)
5. **소스를 고쳤으면 반드시 굽는다.** Debug → F8 → Disconnect까지 해야 보드에 반영된다. 세팅 당일에 "빌드만 하고 안 된다"고 한 번 헛돈 적이 있다.
6. **막히면 3-strike.** 같은 시도 3번 실패하면 방법을 바꾸고, 그 기록을 노트의 네 번째 꼭지에 남긴다.

## 3. 단계별 상세

### 0단계. 발판 만들기

| | 내용 |
|:---|:---|
| 트랙 A | S32DS에서 **빈 프로젝트**를 새로 만들어 LED 토글, SysTick 1 ms 타이머, LPUART printf까지. 클록 트리(SOSC/SPLL → 코어 80 MHz)를 직접 설정하며 `S32K1xx Reference Manual`의 SCG·PCC·PORT 챕터를 읽는다. |
| 트랙 B | NXP FOC 데모의 **코드 지도**를 그린다. `main.c`의 상태머신(Init→Ready→Calib→Align→Run→Fault), `PDB0_IRQHandler`/`ADC1_IRQHandler`가 여는 고속 루프, `FocFastLoop`/`FocSlowLoop`의 데이터 흐름, `meas → FOC → actuate` 경계를 도식화한다. |
| 익히는 개념 | 클록 트리, PCC 게이팅, 포트 mux, 인터럽트 벡터, 링커 스크립트(`S32K144_64_flash.ld`)의 섹션 |
| 완료 기준 | (A) UART로 `printf("%d", tick)`이 1 ms마다 찍힘. (B) 데모의 ISR 3개와 함수 호출 순서를 한 장 그림으로 설명할 수 있음. |
| 산출물 | 저장소 골격(4장), `01. 데모 코드 아키텍처.md` |

### 1단계. PWM과 액추에이터 계층

| | 내용 |
|:---|:---|
| 트랙 A | FTM3를 **레지스터 직접 설정**으로 3상 상보 PWM(20 kHz, 센터 얼라인, 데드타임 0.5 µs)을 낸다. 출력 마스크로 안전 정지, 리로드 시점에 트리거 신호(PDB로 갈 것) 발생까지. |
| 트랙 B | `actuate_s32k.c`의 SVM → 듀티 변환을 **내 SVM 구현**(섹터 판별, 벡터 시간 계산, 3상 듀티)으로 교체. AMMCLib `GMCLIB_SvmStd`와 같은 입력에 같은 출력을 내는지 비교. |
| 익히는 개념 | 상보 PWM과 데드타임의 필요성, 센터 얼라인과 샘플링 관계, 공간벡터 변조 6섹터, 최소·최대 듀티 제한 |
| 완료 기준 | 같은 `uAlBeReq` 입력에 대해 내 SVM과 원본의 3상 듀티 차이 < 1 %. 내 PWM으로 모터가 원본과 같은 전류 파형으로 회전. |
| 산출물 | `02. PWM과 SVM.md`, 듀티 비교 그래프, `phase-1` |

### 2단계. 전류·전압 측정 계층

| | 내용 |
|:---|:---|
| 트랙 A | ADC0/ADC1을 **PDB 트리거**로 PWM 센터에서 동시 샘플링. 12비트 → 물리량 변환, 오프셋 보정(CALIB 상태가 하는 일), DC 버스 전압 IIR 필터를 직접 작성. |
| 트랙 B | `meas_s32k.c`의 2-shunt 측정을 내 코드로 교체. C상 재구성(`ic = -(ia+ib)`), 오프셋 캘리브레이션, 스케일링을 포함. 원본과 동시에 돌려 파형 비교. |
| 익히는 개념 | 2-shunt 샘플링 창의 제약(하측 FET ON 구간에서만 유효), PDB 지연, ADC 인터리브, 센서 오프셋의 영향 |
| 완료 기준 | 정지 상태 오프셋 오차 < 50 mA. 회전 중 내 측정과 원본의 `iDQ` 차이 < 5 %. 샘플링 시점을 PWM 파형 위에 표시한 그림. |
| 산출물 | `03. 전류 측정과 샘플링.md`, `phase-2` |

### 3단계. 게이트 드라이버와 안전

| | 내용 |
|:---|:---|
| 트랙 A | LPSPI0 마스터를 레지스터로 설정하고 **GD3000 드라이버를 처음부터** 작성: 리셋·인에이블 시퀀스, 마스크·모드·데드타임 명령, 상태 레지스터 읽기, 인터럽트 핀 처리. |
| 트랙 B | `Sources/GD3000/*`를 내 드라이버로 교체. 세팅 당일 넣은 **부팅 재시도 패치**([[MCSPTE1AK144 S32K144 모터 제어 키트 세팅 매뉴얼#6.5 Run인데 모터가 안 돌고 전류가 0 — GD3000 초기화 경쟁]])를 설계에 정식 반영. 과전류·과전압·저전압·드라이버 폴트의 처리 흐름을 하나의 폴트 관리자로 정리. |
| 익히는 개념 | SPI 모드(CPOL/CPHA), 부트스트랩·차지펌프, 데드타임 캘리브레이션, 전원 시퀀싱, 폴트 래치와 클리어 정책 |
| 완료 기준 | 냉간 기동 10회 연속 `opMode = 3`. 인위적 폴트(상선 하나 뽑기, 전압 낮추기)에서 1 PWM 주기 안에 출력 차단. |
| 산출물 | `04. 게이트 드라이버와 폴트 처리.md`, 부팅 시퀀스 다이어그램, `phase-3` |

### 4단계. 제어 루프 교체

| | 내용 |
|:---|:---|
| 트랙 A | 고속 루프(10 kHz)와 저속 루프(1 kHz)의 **실행 시간 측정**(GPIO 토글 + 스코프 또는 DWT 사이클 카운터), 인터럽트 우선순위 설계, float 연산 비용, 고정소수점 변환 실험. |
| 트랙 B | 순서대로 교체: (1) 전류 PI(anti-windup 포함) → (2) 속도 PI + 램프 → (3) BEMF 옵저버 + 각도 추적 루프(센서리스). 각 교체마다 AMMCLib 원본과 스텝 응답을 겹쳐 그린다. 여기서 MPC·칼만 지식을 살릴 여지가 생긴다: 옵저버를 EKF로 바꿔 보는 실험을 선택 과제로 둔다. |
| 익히는 개념 | 이산화(Tustin/backward Euler), 대역폭과 샘플링 주기의 관계, 전류 루프 300 Hz가 나온 근거, 센서리스 기동(force → tracking → sensorless) |
| 완료 기준 | 내 전류 PI 스텝 응답 정착 시간이 원본 대비 ±20 % 이내. 내 옵저버로 500~4000 rpm 센서리스 운전 성공. 고속 루프 실행 시간 < 주기의 50 %. |
| 산출물 | `05. 전류·속도 루프.md`, `06. 센서리스 옵저버.md`, 응답 비교 그래프, `phase-4` |

### 5단계. 캡스톤 — CAN 명령 토크·속도 제어 구동기

| | 내용 |
|:---|:---|
| 트랙 A | FlexCAN0 초기화, 메시지 박스 송수신, 500 kbps. PC 쪽은 USB-CAN 어댑터가 없으므로 **EVB 두 번째 보드 또는 UART-CAN 브리지 없이** 우선 루프백 모드로 검증하고, 실기 연결은 장비를 산 뒤로 미룬다. |
| 트랙 B | 로봇 액추에이터 형태로 묶는다: CAN 프레임으로 모드(토크/속도)·목표값·활성화를 받고, 상태(속도·전류·폴트)를 주기 송신. 토크 모드는 `iq` 직접 명령, 전류 한계·속도 한계·폴트 시 안전 정지 포함. |
| 익히는 개념 | CAN 프레임·필터·에러 상태, 명령 프로토콜 설계(하트비트, 타임아웃 시 정지), 실시간 태스크 배치 |
| 완료 기준 | CAN(루프백 또는 실기)으로 토크 명령 → 200 ms 내 응답, 하트비트 끊기면 500 ms 내 정지. 시연 영상 1편. |
| 산출물 | `07. CAN 구동기 캡스톤.md`, README 시연 GIF, `v1.0` 태그 |

### 6단계 (장비 추가 후). 위치·임피던스 제어

엔코더 달린 모터를 사면 추가한다. FTM2 쿼드러처 디코더(J5-01/03, EVB 개조 저항 R166/R168 필요), 위치 루프, 임피던스 제어(`τ = K(θ_ref − θ) − Dθ̇`). 로봇 관절 직무의 핵심이라 최종 포트폴리오 항목으로 둔다.

## 5. 포트폴리오로 만드는 법

면접관이 보는 것은 "모터를 돌렸다"가 아니라 **"무엇을 스스로 만들었고, 어떻게 검증했고, 무엇이 막혔을 때 어떻게 풀었나"** 이다. 그래서 각 단계 노트의 네 꼭지가 그대로 이력서 항목이 된다.

| 이력서 한 줄 | 근거가 되는 산출물 |
|:---|:---|
